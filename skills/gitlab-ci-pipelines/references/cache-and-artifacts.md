## Чем отличаются

|                   | Артефакты                                      | Кэш                                                              |
|-------------------|------------------------------------------------|------------------------------------------------------------------|
| Назначение        | передать результат джобы другим джобам и людям | ускорить повторную установку зависимостей                        |
| Гарантия доставки | есть                                           | нет, кэша может не оказаться                                     |
| Где хранится      | в GitLab                                       | на раннере или в распределённом кэше (S3, GCS), если он настроен |
| Кому виден        | джобам пайплайна, плюс скачивание из UI и API  | любым пайплайнам с тем же ключом                                 |
| Срок жизни        | `expire_in`                                    | пока не вытеснят или не очистят                                  |

Правило выбора: если следующая джоба без этих файлов упадёт, нужен артефакт. Если без них она просто будет дольше,
подойдёт кэш.

## Кэш

```yaml
.npm-cache:
  variables:
    npm_config_cache: $CI_PROJECT_DIR/.npm
  cache:
    key:
      files:
        - package-lock.json
    paths:
      - .npm/
    policy: pull
```

- Кэшировать можно только пути внутри `$CI_PROJECT_DIR`. Поэтому кэш инструментов перенаправляют в папку проекта
  (таблица ниже).
- Ключ строй от lock-файлов (`key:files`, до двух файлов): поменялись зависимости, появился новый кэш. Имя ветки в ключе
  (`$CI_COMMIT_REF_SLUG`) изолирует ветки, но новая ветка стартует с пустым кэшем; это смягчает `fallback_keys`.
- `policy`: загрузка кэша после джобы стоит времени. Пусть кэш обновляет одна джоба (или только основная ветка) с
  `pull-push`, остальные читают с `pull`.
- В одной джобе можно указать несколько кэшей списком.
- Кэш раннера локален. Если раннеров несколько, а распределённого кэша нет, попадания будут редкими; выясни это заранее
  (в AGENTS.md или CLAUDE.md проекта либо у пользователя).
- Для защищённых и незащищённых веток кэши по умолчанию раздельные: MR-ветки не видят кэш, собранный на `main`. Учитывай
  это, когда кэш «почему-то холодный».

Обновлять кэш только с основной ветки можно через переменную в `policy` (поддерживается в свежих версиях):

```yaml
build:
  rules:
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
      variables:
        CACHE_POLICY: pull-push
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
      variables:
        CACHE_POLICY: pull
  cache:
    key:
      files:
        - package-lock.json
    paths:
      - .npm/
    policy: $CACHE_POLICY
  script:
    - ./scripts/ci/build.sh
```

## Куда перенаправить кэш инструментов

| Инструмент | Переменная или настройка                                        | Что кэшировать                        | Ключ от                                                |
|------------|-----------------------------------------------------------------|---------------------------------------|--------------------------------------------------------|
| npm        | `npm_config_cache: $CI_PROJECT_DIR/.npm`                        | `.npm/`                               | `package-lock.json`                                    |
| pnpm       | `pnpm config set store-dir .pnpm-store` в `before_script`       | `.pnpm-store/`                        | `pnpm-lock.yaml`                                       |
| pip        | `PIP_CACHE_DIR: $CI_PROJECT_DIR/.cache/pip`                     | `.cache/pip/`                         | `requirements.txt` или `poetry.lock`                   |
| Go         | `GOPATH: $CI_PROJECT_DIR/.go`                                   | `.go/pkg/mod/`                        | `go.sum`                                               |
| Maven      | `MAVEN_OPTS: -Dmaven.repo.local=$CI_PROJECT_DIR/.m2/repository` | `.m2/repository/`                     | `pom.xml`                                              |
| Gradle     | `GRADLE_USER_HOME: $CI_PROJECT_DIR/.gradle`                     | `.gradle/caches/`, `.gradle/wrapper/` | `gradle-wrapper.properties` и файл версий зависимостей |
| Cargo      | `CARGO_HOME: $CI_PROJECT_DIR/.cargo`                            | `.cargo/registry/`, `.cargo/git/`     | `Cargo.lock`                                           |

- Если у сборочной системы есть свой удалённый кэш результатов (Gradle build cache, Bazel, Nx, Turborepo), кэш задач
  держи там: он общий для всех раннеров и разработчиков. GitLab-кэш тогда оставь для скачанных зависимостей.
- Демоны сборки в одноразовом контейнере не переиспользуются, в CI их обычно отключают.
- Большой кэш может скачиваться и распаковываться дольше, чем экономит. Сравни время джобы с кэшем и без и при
  необходимости сузь `paths`.

## Артефакты

```yaml
build:
  script:
    - ./scripts/ci/build.sh
  artifacts:
    paths:
      - build/output/
    expire_in: 3 days

unit-tests:
  script:
    - ./scripts/ci/unit-tests.sh
  artifacts:
    when: always
    reports:
      junit: build/test-results/**/*.xml
    expire_in: 1 week
```

- `expire_in` задавай всегда. Иначе действует настройка инстанса, а место в хранилище заканчивается незаметно. Артефакты
  последнего успешного пайплайна ветки по умолчанию хранятся бессрочно, это отдельная настройка проекта.
- `paths` ограничивай тем, что действительно нужно дальше. Каждая джоба-потребитель скачивает всё целиком.
- По умолчанию джоба скачивает артефакты всех джоб из предыдущих стадий. С `needs` скачиваются только артефакты
  перечисленных джоб; `dependencies: []` или `needs: []` отключают скачивание совсем.
- `when: always` нужен отчётам и логам: они ценнее всего как раз при падении.
- `expose_as` показывает ссылку на артефакт прямо в MR.

## Отчёты и передача переменных

| Отчёт                                 | Что даёт                                    |
|---------------------------------------|---------------------------------------------|
| `reports:junit`                       | упавшие тесты видны в MR и во вкладке Tests |
| `reports:coverage_report` (cobertura) | подсветка покрытия в diff MR                |
| `reports:codequality`                 | замечания статанализа в MR                  |
| `reports:dotenv`                      | переменные для следующих джоб               |

Передать значение, вычисленное в одной джобе, в другие:

```yaml
version:
  script:
    - echo "APP_VERSION=$(./scripts/ci/version.sh)" >> build.env
  artifacts:
    reports:
      dotenv: build.env

release:
  needs: [ version ]
  script:
    - ./scripts/ci/release.sh "$APP_VERSION"
```

## Сжатие и скорость

```yaml
variables:
  FF_USE_FASTZIP: "true"
  ARTIFACT_COMPRESSION_LEVEL: fast
  CACHE_COMPRESSION_LEVEL: fast
```

Быстрое сжатие обычно окупается: на больших кэшах и артефактах упаковка по умолчанию занимает заметную часть времени
джобы.
