# Типичные ошибки

Используй при ревью и рефакторинге. Порядок ревью: `workflow:rules` → матрица «событие × джобы» → граф `needs` → каждая
джоба по чеклисту из SKILL.md.

## Когда и что запускается

| Ошибка                                                                    | Чем плохо                                                                    | Как исправить                                                        |
|---------------------------------------------------------------------------|------------------------------------------------------------------------------|----------------------------------------------------------------------|
| Нет `workflow:rules`                                                      | дубли пайплайнов branch + MR, раннеры делают работу дважды                   | шаблон из [rules-and-workflow.md](rules-and-workflow.md)             |
| `only` / `except`                                                         | не развиваются, не комбинируются с `rules`                                   | переписать на `rules`                                                |
| Одинаковые `rules` скопированы в каждую джобу                             | правки расходятся                                                            | шаблоны правил по событиям + `extends` / `!reference`                |
| Новая джоба со своими правилами в проекте, где правила вынесены в шаблоны | условия расходятся, структура расползается                                   | подключить существующий шаблон или добавить новый рядом с остальными |
| `extends: [.rules-mr, .rules-main]`, чтобы объединить условия             | массивы при `extends` заменяются, работают только правила последнего шаблона | `!reference` на каждый шаблон                                        |
| Шаблон основной ветки без исключения расписаний                           | ночной пайплайн на `main` запускает деплой и прочие джобы основной ветки     | `$CI_PIPELINE_SOURCE != "schedule"` в условии                        |
| `rules:changes` в branch-пайплайне без `compare_to`                       | на новой ветке и по расписанию всегда истинно                                | `compare_to` или `changes` только в MR-правилах                      |
| У всех джоб MR-пайплайна есть `changes`                                   | MR без подходящих изменений остаётся без пайплайна и не мёржится             | джоба без `changes` вне `.pre`/`.post`, проверка скриптом            |
| Тяжёлые джобы на каждый коммит в MR                                       | очередь на раннеры, медленный фидбек                                         | `changes`, лейбл на MR, ручной запуск, ночное расписание             |
| Ручная джоба в `rules` неожиданно блокирует пайплайн                      | там `allow_failure: false` по умолчанию                                      | явно `allow_failure: true`, если блокировка не нужна                 |
| Джобы в дочернем пайплайне проверяют `merge_request_event`                | источник там `parent_pipeline`, джобы не появляются                          | условие `if: $CI_MERGE_REQUEST_ID`, см. child-pipelines.md           |
| Триггер-джоба дочернего пайплайна без `strategy`                          | родитель зелёный раньше дочернего, отчёты не попадают в MR                   | `strategy: mirror` (или `depend` на старых версиях)                  |
| Дочерний пайплайн ждёт переменную из расписания                           | `pipeline_variables` по умолчанию не передаются                              | `trigger:forward:pipeline_variables: true`                           |
| `when: always` без причины                                                | джобы бегут после падения и тратят ресурсы                                   | оставить только для уборки и отчётов                                 |

## Граф и скорость

| Ошибка                                           | Чем плохо                                        | Как исправить                                          |
|--------------------------------------------------|--------------------------------------------------|--------------------------------------------------------|
| Порядок задан только стадиями                    | все ждут самую медленную джобу стадии            | `needs`                                                |
| Джобы скачивают артефакты всех предыдущих стадий | лишние гигабайты в каждой джобе                  | `needs` или `dependencies: []`                         |
| Результаты сборки передаются через кэш           | кэш может не найтись, отсюда «случайные» падения | артефакты                                              |
| Артефакты без `expire_in` или с широкими `paths` | забитое хранилище, медленные загрузки            | `expire_in`, узкие `paths`                             |
| Все джобы делают `pull-push` кэша                | каждая тратит время на загрузку                  | `pull-push` у одной джобы или только на основной ветке |
| Нет `timeout`                                    | зависшая джоба держит раннер до лимита проекта   | `timeout` под реальное время                           |
| Нет `interruptible` и автоотмены                 | устаревшие пайплайны догоняют свежие             | `interruptible: true` + `workflow:auto_cancel`         |

## Надёжность

| Ошибка                                         | Чем плохо                                  | Как исправить                                                    |
|------------------------------------------------|--------------------------------------------|------------------------------------------------------------------|
| `retry: 2` на всё                              | флаки невидимы, время удваивается          | `retry:when` с инфраструктурными причинами                       |
| `allow_failure: true` на тестах                | красные тесты никто не видит               | починить, или карантин с задачей, или `allow_failure:exit_codes` |
| `image: something:latest`                      | сборка зависит от дня запуска              | конкретный тег или digest                                        |
| `include: project` без `ref` или с `ref: main` | изменение шаблона ломает все проекты сразу | `ref` на тег                                                     |
| Потребитель смёржен с `ref` на ветку шаблона   | изменения шаблона приезжают без ревью      | вернуть тег до мёржа, см. includes-and-components.md             |
| Деплой с `interruptible: true`                 | новый коммит обрывает деплой на середине   | `interruptible: false`                                           |
| Деплой без `resource_group`                    | два деплоя в одно окружение одновременно   | `resource_group`                                                 |

## Поддерживаемость

| Ошибка                                                 | Чем плохо                                   | Как исправить                                    |
|--------------------------------------------------------|---------------------------------------------|--------------------------------------------------|
| Скопированные джобы с мелкими отличиями                | правки расходятся, файл растёт              | `extends`, `parallel:matrix`, компонент          |
| YAML-якоря между файлами                               | не работают через `include`                 | `extends`, `!reference`                          |
| 30+ строк bash в `script`                              | не запустить локально, не протестировать    | `scripts/ci/*.sh` или задача сборочной системы   |
| Наследование `extends` глубже 3 уровней                | невозможно понять итоговую джобу            | сплющить, часть вынести в `!reference`           |
| Один файл на несколько областей или длиннее ~200 строк | тяжело ревьюить и мёржить                   | `.gitlab/ci/<область>.yml` + `include: local`    |
| Файлы по стадиям (`build.yml`, `test.yml`)             | одна область размазана по нескольким файлам | файлы по областям: `backend.yml`, `frontend.yml` |
| Комментарии-разделители `# --- ... ---`                | шум, расходятся с кодом при правках         | убрать; комментировать только неочевидное        |

## Безопасность

| Ошибка                                       | Чем плохо                             | Как исправить                                       |
|----------------------------------------------|---------------------------------------|-----------------------------------------------------|
| Секреты в YAML или в репозитории             | утечка через историю git              | CI/CD-переменные, `id_tokens`                       |
| `echo $TOKEN`, `set -x`, `curl -v`           | секрет в логе                         | убрать вывод, маскировать, не включать трассировку  |
| Снят флаг protected, «чтобы заработало в MR» | креды доступны коду из любой ветки    | вернуть protected, деплой только с защищённых веток |
| Подпись и деплой на общих раннерах           | ключи доступны всем джобам на раннере | отдельные protected-раннеры                         |
